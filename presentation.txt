СЛАЙД 1: Введение в проект «Календарь мероприятий КузГТУ»

Проект «Календарь мероприятий КузГТУ» — это веб-приложение, которое я сделала для нашего университета. Главная идея — собрать все мероприятия КузГТУ в одном месте, чтобы было удобно смотреть, что и когда проходит. Студенты, преподаватели и другие сотрудники могут зайти и увидеть список событий с датами, временем и местами. Можно добавлять новые мероприятия, менять информацию в старых или удалять их, если они уже не актуальны. Я старалась сделать интерфейс простым, чтобы даже те, кто не сильно разбирается, могли легко разобраться. В целом, проект помогает решить проблему, когда информация о событиях разбросана по разным местам — теперь всё в одном месте.


СЛАЙД 2: Используемые технологии проекта

Для проекта я использовала разные технологии, которые изучал. Основу составляет набор инструментов для веб-разработки. Серверная часть написана на Python (версии 3.8 или новее) с использованием Flask — это такой фреймворк, который помогает создавать веб-приложения и он довольно простой в использовании. Чтобы работать с базой данных, я подключил Flask-SQLAlchemy — это библиотека, которая позволяет управлять данными как объектами. Сама база данных — SQLite, она удобная тем, что не нужно ничего отдельно настраивать, всё работает из коробки. Внешняя часть сделана на обычном HTML и CSS3, без всяких дополнительных библиотек, чтобы страницы грузились быстро. Для генерации HTML-страниц используется Jinja2, он идёт вместе с Flask. В общем, я выбрал такие инструменты, чтобы проект было легко запустить и поддерживать, и чтобы он не требовал мощного сервера.


СЛАЙД 3: Архитектура и структура проекта

Проект построен по обычной схеме для веб-приложений. Главный файл app.py содержит основную логику: там описана модель данных Event (это события), настроены маршруты для разных страниц и обработка форм. В модели Event есть поля: id, название, описание, дата, время, место и дата создания записи. В папке templates лежат три HTML-шаблона: index.html — главная страница со списком мероприятий, add_event.html — форма для добавления нового события, edit_event.html — форма для редактирования. Файлы стилей (style.css) и другие статичные файлы находятся в папке static. База данных events.db создаётся сама в папке instance, когда запускаешь приложение первый раз. Структура похожа на паттерн MVC: модель — это класс Event, вид — HTML-шаблоны, а контроллер — функции во Flask, которые обрабатывают запросы. Такое разделение помогает держать код в порядке.


СЛАЙД 4: Функциональные возможности системы

В системе есть несколько основных функций для работы с мероприятиями. На главной странице все события показаны в виде карточек, они отсортированы по дате и времени. Те мероприятия, которые уже прошли, выделены другим цветом, чтобы их было легче отличить. Можно добавить новое событие — обязательно нужно указать название и дату, а время, место и описание — по желанию. Если нужно изменить информацию о событии, есть форма редактирования. При удалении события система спрашивает подтверждение, чтобы случайно ничего не удалить. Также есть всплывающие сообщения, которые показывают, успешно ли выполнилось действие или где ошибка в форме. Дизайн адаптирован под разные устройства — нормально смотрится и на компьютере, и на телефоне, что важно, чтобы все могли зайти и посмотреть информацию.


СЛАЙД 5: Обоснование выбора решений и перспективы развития

Я выбрал такие технологии, потому что хотел сделать проект простым в установке и поддержке, особенно для учебной среды. Flask подошёл хорошо — он лёгкий и не такой сложный, как большие фреймворки. SQLite удобен тем, что не нужно быть администратором баз данных, чтобы с ним работать, это отлично для небольших проектов вроде нашего. Я не стала использовать JavaScript, чтобы уменьшить возможные проблемы с безопасностью и ускорить работу. Для оформления взяла фирменные цвета КузГТУ — тёмно-синий (#061A44) для верхней части и светлые цвета для остального, чтобы было похоже на стиль университета. В будущем проект можно развивать: добавить вход по логину и паролю, возможность сохранять события в личный календарь, подключить соцсети вуза или сделать категории для событий. Сейчас это хорошая основа, которую можно улучшать, и она показывает, как можно применять навыки программирования для решения реальных задач в университете.
